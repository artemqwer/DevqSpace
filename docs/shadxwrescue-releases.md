# Выпуски ShadxwRescue на DevqSpace

Публичная страница находится в `/shadowrescue`, управление выпусками — в
`/admin/shadxwrescue`. При пустом каталоге страница показывает статус беты.

## Настройка

- Используйте текущий постоянный Redis DevqSpace.
- Подключите отдельный **приватный** Vercel Blob и добавьте его токен как
  `SHADXWRESCUE_BLOB_TOKEN`. Токен существующего публичного Blob не меняется.
- Для раздачи нужно, чтобы хранилище поддерживало подписанные Blob URL.
  Публичный маршрут выдаёт подписанную ссылку на конкретный ISO на один час.
  Скачивание идёт из Blob. При отзыве прекращается выдача новых ссылок,
  ранее выданные могут оставаться действительными до истечения срока.

## Локальная проверка

Из корня сайта выполните `npm run test:shadxwrescue` (Node.js 22.18+).
Тесты вызывают обработчики приложения с имитацией Redis и Blob. Они проверяют
доступ к ISO и контрольной сумме, права на загрузку, отказ при несовпадении
размера или SHA-256, публикацию, параллельные запросы и отзыв выпуска. Для
этой проверки не нужны ключи или подключение к хранилищу.

После этого запустите сайт локально: `npm run dev -- --hostname 127.0.0.1 --port 3043`.
Откройте `http://127.0.0.1:3043/shadowrescue` и проверьте галерею, мобильную
раскладку и админку. Для проверки реальной передачи файла используйте отдельные
тестовые Redis и приватный Blob с поддержкой подписанных URL, затем проверьте
скачивание и SHA-256 до подключения продакшен-хранилищ.

## Выпуск из админки

Создайте черновик с версией, архитектурой, размером, SHA-256, коммитом, изменениями и
реальными результатами проверок. Выберите ISO и дождитесь завершения прямой загрузки.
Нажмите «Перевірити й опублікувати». Сервер потоково сверит байты и SHA-256, затем
откроет карточку и загрузку. Пока проверка не завершилась, выпуск остаётся приватным.

ISO по одному пути нельзя перезаписать. После неудачной загрузки можно выделить
новый путь в том же черновике. Старые объекты остаются в приватном Blob.
Удаляйте ненужные объекты через консоль хранилища после проверки, что на их пути
нет ссылки из действующих выпусков или черновиков.

Архитектуры выпускаются отдельно. Указывайте только проверенную совместимость.
Исправленный публичный ISO получает новый номер версии. При отзыве причина
остаётся в истории.

## Выпуск с рабочего ПК

Из корня сайта, с Node.js 22 или новее и установленными зависимостями:

```powershell
node scripts/shadxwrescue-release.mjs prepare путь.iso 1.0.0-beta.1 x86-64 ПОЛНЫЙ_КОММИТ changes.txt checks.txt > release.json
node scripts/shadxwrescue-release.mjs stage https://www.devq.space путь.iso release.json
node scripts/shadxwrescue-release.mjs publish https://www.devq.space 1.0.0-beta.1-x86-64
```

Для `stage` и `publish` передайте действующий ключ админки через переменную
окружения `SHADXWRESCUE_ADMIN_KEY`. Команда `stage` создаёт или повторно использует
совпадающий приватный черновик, сверяет локальный файл с манифестом и загружает
образ напрямую. Публикация выполняется отдельной командой или вручную в админке.
